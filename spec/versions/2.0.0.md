# 2.0.0 — multi-file store, local password identity, fresh start

Status: superseded by 2.0.1. Delivered and deployed; release verification was not independent
acceptance.

## Scope

Persistence rebuilt from `localStorage['runawaylog-data']` into a device-local IndexedDB virtual
file tree (`accounts/<accountId>/`, run history chunked by month, one file per plugin, derived
index, generation-atomic commit, recovery and GC). Archive interchange is `runawaylog-files` ZIP
format 1 with a manifest and per-payload SHA-256; 1.2.0 `.json` exports are not importable.
Local sign-in became username-first with a locally set password (PBKDF2-HMAC-SHA-256, 16-byte
salt, 210,000 iterations) kept outside the account tree, manifest and archive. 2.0.0 starts from
an empty store: 1.2.0 on-device data and `localStorage` keys are ignored, neither migrated nor
deleted. Cloud storage stays designed and disabled. Dependency audit went from 33 advisories
(2 critical, 20 high) to 12 (none critical or high).

## Decisions

- Multi-file store, account directory by UUID with the handle inside `account.json`, no OPFS, no
  server, no desktop wrapper — folded into [storage](../facts/storage.md).
- Pure PostgreSQL plus a thin API as the future cloud model; no Supabase, no RLS, no hosted auth;
  cloud off in this version — folded into [cloud](../facts/cloud.md).
- Local password identity, no recovery by design, credentials outside the account tree — folded
  into [identity](../facts/identity.md).
- Minimum password length six characters; UI says "at least 6 characters".

## Verification

Gates on the release commit: `eslint` 0, `tsc -b` 0, `vitest` 51 files / 555 cases, `build` 0.
Archive round trip measured on the real build: 13 entries, manifest `runawaylog-files`
`formatVersion 1`, 12 payloads matching SHA-256 and byte counts, import into a fresh browser
context reproducing hit counts and timestamps. Production smoke in host Chromium: username-first
login, first-use password setup, one Run, reload persistence, About showing 2.0.0.

## Known limitations

Serious colour-contrast findings on four surfaces (Login 1 node, Home 24, Settings 1, Print
22 plus one `scrollable-region-focusable`) recorded and deferred. Firefox unverified on the
build host (Playwright/browser revision mismatch). Power-loss durability is a design guarantee
with injectable fault tests, not a tested claim. Same-tab reload keeps the session; a new tab
authenticates again. The smoke used `serviceWorkers: 'block'`, so the update path was not
exercised — which is exactly the defect 2.0.1 fixed.
