# i18n contract

Three locales: `en_us`, `zh_cn`, `zh_tw`, as typed TypeScript modules.

```
src/lib/i18n/
  locales/en_us.ts      the reference locale; its type defines every key
  locales/zh_cn.ts
  locales/zh_tw.ts
  index.ts              useT(), t(key, vars), fallback rules
src/test/i18n-structure.test.ts   key set, placeholders, parity, markup subset
src/test/i18n-hardcoded.test.ts   no user-visible literal outside the locale modules
src/test/i18n-surfaces.test.tsx   every surface renders in all three locales
```

The XML source, `xml-to-ts.js`, the two hash baselines and the projection exceptions are
gone (removed in 1.1.0). There is no generated file to regenerate before a commit and no
baseline to re-approve.

## The contract, executable

1. The three locale modules expose an identical key set — missing and extra keys both fail,
   with the key path in the message.
2. The same placeholder set appears in every locale for a given key.
3. No CJK characters in `en_us`; no untranslated `en_us` value in a CJK locale unless the
   string is a proper noun (a short allowlist in the test).
4. No user-visible string literal in `src/features` or `src/ui`.
5. A key that renders inline markup is a plain string with a documented subset (`<b>`,
   `<br>`) rendered through one helper — not `dangerouslySetInnerHTML` scattered through
   components. Angle brackets that are not markup (for example a file path written
   `accounts/[id]/…`) stay literal so the markup check does not read them as tags.

## Working rules

- `en_us` is the type source. `zh_cn` and `zh_tw` are typed as the same shape, so a missing
  or extra key is a compile error, not a runtime blank.
- Interpolation is `{name}` placeholders through one `t()` implementation. No component
  builds a sentence by concatenating translated fragments.
- Adding a string = adding it to all three modules in the same commit; changing a string =
  changing three files. That is the honest cost of three locales.
- Locale choice is a device preference, read by `lib/i18n` only. Switching locale is a state
  change, not a reload, and never resets scroll or an open dialog.
- Copy is user-facing and follows the owner's rule: short, no implementation vocabulary
  ("code point", "UTF-8", "Unicode" never appear in shipped text). A test enforces the
  password-copy case; the same standard applies to every new string.
